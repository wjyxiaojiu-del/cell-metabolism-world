# 公开 Beta 就绪规格

## Problem Statement

细胞代谢世界地图已经具备稳定的生物学容纳层级、55 条通路、343 条反应和 21 条核心专家通路，但还不能诚实地称为“可公开 Beta”：科学审校台账仍有 40 条 `待审校`；部分核心机制图在 390px 手机视口中只能缩小显示，关键文字和触控目标难以可靠阅读与操作；现有门禁分别覆盖数据、几何和 UI，却没有一个能够证明公开 Beta 条件全部满足的总入口。

## Solution

建立一条可重复执行的公开 Beta 完成路径：逐条处理剩余科学审校项，并依据证据选择精确反应、净反应、示意边、货物流、转运或机制未明转运，不以批量改状态代替审校；为全部 21 条核心专家通路提供 390px 手机端可读的机制视图和足够大的主要触控目标；最后用一个顶层 Beta 门禁聚合科学审校、数据一致性、专家通路几何和全量浏览器回归。

## User Stories

1. 作为公开 Beta 体验者，我希望地图中的每条反应都有明确审校结论，以便知道内容不是未经确认的草稿。
2. 作为生物化学学习者，我希望示意边与精确反应在语义上明确区分，以免把教学概括误认为精确计量。
3. 作为科学审校者，我希望每条终审结论都能追溯到 Rhea、Reactome、KEGG、UniProt 或 PubMed 证据，以便复核。
4. 作为科学审校者，我希望机制不明确的转运被诚实标注为有限结论，以免系统虚构具体载体。
5. 作为科学审校者，我希望跨区室过程在必要时拆分为化学反应、货物流和转运，以便区室与方向保持正确。
6. 作为地图维护者，我希望审校完成意味着台账中没有 `待审校`，而不是仅修改统计数字。
7. 作为手机用户，我希望在 390px 宽度下看清核心机制图的关键节点、酶和方向，以便不依赖桌面设备学习。
8. 作为手机用户，我希望机制图内的次要说明不会挤压关键标签，以便快速识别主链。
9. 作为手机用户，我希望需要放大的机制图在地图内部平移或缩放，而不是导致整页横向滚动。
10. 作为触屏用户，我希望主要导航、缩放、返回、关闭和通路选择目标足够大，以便稳定点击。
11. 作为键盘用户，我希望所有主要操作仍具有名称、焦点状态和可预测的顺序，以便不依赖指针设备。
12. 作为专家地图用户，我希望从完整细胞进入通路时仍遵守生物学容纳层级，以免移动端优化破坏现有导航真相。
13. 作为专家地图用户，我希望 21 条核心通路都能进入正确场景并显示机制节点，以免只有代表性通路得到优化。
14. 作为学生模式用户，我希望专家地图优化不改变学生通路的教学归属和步骤链接，以便原有课程继续工作。
15. 作为平板用户，我希望 768px 下保留完整机制图、触摸缩放和全屏行为，以免手机规则误伤平板。
16. 作为桌面用户，我希望 1440px 下继续获得完整信息密度，以免响应式规则过度简化桌面机制图。
17. 作为维护者，我希望一个命令能够判断当前版本是否满足公开 Beta 条件，以便发布前无需拼凑多份结果。
18. 作为维护者，我希望 Beta 门禁输出具体失败项和源行，以便快速定位科学或 UI 回归。
19. 作为维护者，我希望现有 55 条通路、343 条反应和学习步骤继续通过交叉一致性检查，以免审校拆分造成悬空引用。
20. 作为发布负责人，我希望全量浏览器回归无失败、无控制台错误和关键资源加载失败，以便公开测试建立在可重复证据上。

## Implementation Decisions

- 保持现有领域语言：物质、节点、区室、反应、转运反应、场景、场景热点组和通路节点组不变。
- 遵守已接受的专家层级决策；移动端呈现不得重新引入教学层作为专家地图导航真相。
- 科学审校按现有三维政策分别记录审校状态、表示类型和证据。
- 40 条待审校记录必须逐条解决。可以修正、拆分或限定结论，但不得仅为清零而批量提升状态。
- 非精确反应必须在备注中说明抽象边界；机制未明转运只终审“存在该有限区室连接”的结论。
- 全部 21 条核心专家通路纳入 390px 验收，不以少数代表性通路替代全覆盖。
- 手机机制视图优先显示关键物质、酶/载体、方向和区室；次要解释进入可展开详情。
- 手机端允许机制画布内部平移和缩放，但文档页面本身不得产生横向溢出。
- 主要触控目标以约 44×44 CSS 像素为下限；不可见或纯装饰元素不计入触控门禁。
- 桌面与平板保留现有信息密度和手势行为，手机规则通过响应式状态隔离。
- 新增一个顶层公开 Beta 门禁，聚合审校完成度、引用格式、数据门禁、21 条专家通路和全量 UI 回归。
- 不新增新的领域概念或不可逆架构决策，因此本规格不新增 ADR。

## Testing Decisions

- 测试只验证公共行为和可观察结果，不断言内部函数调用或私有布局常量。
- 最高测试接缝是公开 Beta 总门禁：单一命令应在任一必要条件不满足时失败，并给出具体原因。
- 科学接缝验证审校台账零 `待审校`、引用格式有效、源反应与台账一致以及编译和交叉引用通过。
- 移动端接缝使用真实 390×844 浏览器视口遍历全部 21 条核心通路。
- 每条核心通路验证：入口可加载、进入正确场景、机制节点存在、页面无横向溢出、关键标签位于机制视口内、主要操作目标满足触控尺寸。
- 保留现有 768px iPad 手势/全屏测试和 1440px 专家布局测试作为回归保护。
- 复用现有数据校验、专家几何校验、学生步骤链接和 Playwright 测试模式。
- 对移动端新增失败测试后再实现响应式行为；每个科学审校 ticket 在修改前先添加或收紧对应数据门禁/回归用例。
- 最终必须运行数据门禁、21 条专家通路定向回归和全量浏览器回归；窄测试通过不能替代全量结果。
- 视觉截图用于人工审阅；在建立正式基线前，不把截图存在本身表述为像素级视觉回归通过。

## Out of Scope

- 新增第 56 条及之后的通路。
- 改变学生模式的教学课程结构。
- 重写专家地图的生物学容纳层级。
- 部署托管、账号系统、用户数据收集或正式生产运维。
- 为所有 55 条通路一次性制作全新插画；本轮只保证 21 条核心通路的手机机制表达可读。
- 将未知载体猜测成具体蛋白以换取终审状态。
- 与公开 Beta 条件无关的大规模框架迁移。

## Further Notes

- 当前基线为 55 条通路、343 条反应、306 个节点、21 条核心专家通路和 75 条浏览器回归。
- 当前科学审校台账有 40 条 `待审校`，其中主要风险集中在区室机制、多步合并、抽象类别和细胞事件。
- 当前 390px 页面无横向溢出，但若干机制图原生小字和 32–40px 触控目标尚未达到本规格。
- 科学证据获取和终审必须遵守项目科学审校政策，引用需通过离线格式检查，并在网络可用时执行在线检查。
