# 第六周：负责人签核收口与最终审计规格

状态：已确认，待按 tickets 实现

所属项目总目标：42/42 学习地图与专家地图全部通过

## Problem Statement

第五周的工程施工目标已经完成：21 条核心通路的 42 张学习地图与专家地图均已完成内部复审、评分、三档证据和自动化门禁。但负责人签核表仍为 0/42，当前没有一个只读的公共审计接缝能同时核对负责人状态、内部台账、评分门槛和 126 张 canonical final 证据。

如果继续依赖手工数表，可能出现负责人状态已变更但台账未同步、通过状态没有确认日期、证据缺档、或内部评分低于门槛仍被计入正式完成数等问题。

## Solution

第六周限定为“负责人签核支持与最终审计准备”，不新增学习或专家产品功能，不扩展 21 条核心通路范围，不代替项目负责人填写确认日期。

1. 固化一份签核包，按通路对列出学习图、专家图、390/768/1440 三档操作要求、内部评分、P0/P1、证据路径和退回记录规则。
2. 增加只读的负责人签核一致性命令。命令从负责人签核表、双地图审查台账和 evidence 目录读取数据，输出正式完成数、证据数、门槛失败项和待处理阻塞；任何必要条件不满足时返回非零退出码。
3. 固化退回闭环：负责人退回时保留问题说明，正式完成数不增加；修复后只重新生成对应通路对的 final 证据并运行针对性测试，再等待负责人重新确认。
4. 42/42 签核后，使用同一审计命令生成最终收口结果，再运行一次 `npm test`。发布、用户招募和产品扩展仍不属于本周交付。

## User Stories

1. 作为项目负责人，我希望按通路对看到学习图和专家图的完整签核上下文，以便一次确认事实、空间、教学、视觉和交互是否一致。
2. 作为项目负责人，我希望在 390、768、1440 三档实际操作后记录同一通路对的结论，以便不把单一视口体验当成全量通过。
3. 作为项目负责人，我希望通过状态必须带确认日期，以便正式完成数只来自本人明确确认。
4. 作为项目负责人，我希望退回状态必须带有问题说明，以便修复范围可追踪。
5. 作为维护者，我希望命令能确认负责人表包含 21 个通路对，以便缺行不会被静默忽略。
6. 作为维护者，我希望命令能确认学习图和专家图的通路集合一致，以便一侧遗漏不会被计数掩盖。
7. 作为维护者，我希望命令能确认每张地图有 390、768、1440 三档 canonical final 证据，以便缺截图时明确失败。
8. 作为维护者，我希望命令能确认每张地图总分至少 90、科学分至少 24，且 P0/P1 均为零，以便正式完成数不绕过内部门槛。
9. 作为维护者，我希望命令能确认负责人表和内部审查台账的通路及状态一致，以便人工更新不会产生双重事实来源。
10. 作为维护者，我希望命令失败时列出具体通路、视口或字段，以便直接定位阻塞项。
11. 作为维护者，我希望命令默认只读，以便审计不会自动填写负责人状态、日期或评分。
12. 作为负责人，我希望退回一条通路后正式完成数保持不变，以便退回不会被误报为已完成。
13. 作为维护者，我希望修复退回项后只更新对应通路对的证据和回归记录，以便变更范围可控。
14. 作为项目负责人，我希望 42/42 通过后能看到一次最终总审计结果，以便决定是否进入后续 Beta 评估。
15. 作为项目团队，我希望第六周不改变学生模式、专家模式导航和 21 条核心通路边界，以便收口期间保持产品冻结。

## Implementation Decisions

- 负责人签核表是负责人确认的唯一写入入口；自动化只能读取、核对和报告，不能把 `待确认` 批量改为 `通过`。
- 签核状态使用 `待确认`、`通过`、`退回`。`通过` 必须有确认日期；`退回` 必须有退回项；`待确认` 不得被计入正式完成数。
- 审计命令以现有 Markdown 台账和 evidence 目录为输入，采用项目既有的通路 ID、评分格式 `总分/科学分` 和 21 条核心清单。
- canonical evidence 只统计文件名符合 `YYYY-MM-DD-final-390.png`、`YYYY-MM-DD-final-768.png`、`YYYY-MM-DD-final-1440.png` 的三档地图主体截图；地图详情、overlay、deck 和历史证据不替代这三档。
- 命令支持只读人类可读输出，并提供机器可读 JSON 输出；发现任何阻塞时退出码为 1。
- 审计命令可通过显式项目根目录参数读取测试 fixture，但默认读取当前项目根目录；不写入任何项目文件。
- 退回修复继续沿用现有数据源、编译、布局、截图和针对性 UI 回归流程；本周不引入新的产品交互。

## Testing Decisions

- 最高测试接缝是审计命令的 CLI 行为：给定一组公开的台账和证据目录，验证输出摘要、失败原因和退出码。
- 测试覆盖完整通过、负责人未确认、确认日期缺失、退回项缺备注、评分不足、P0/P1 非零、证据缺档、重复 canonical evidence、学习/专家通路集合不一致和台账状态不一致。
- 测试使用临时 fixture 目录和命令行公共参数，不调用内部解析函数，不 mock 文件系统实现。
- 现有 `npm test`、数据门禁、专家几何门禁和移动端回归继续作为签核后的最终总回归；第六周命令通过独立的 `audit:owner-signoff` 脚本执行，不并入默认 `npm test`，因为签核未完成时非零退出是预期阻塞。
- 负责人实际查看和操作 390/768/1440 仍是人工验收，自动化命令只验证记录和证据完整性，不宣称替代人工视觉确认。

## Out of Scope

- 新增通路、扩展 21 条核心清单或改变学生/专家产品功能。
- 代替项目负责人填写确认日期或签核结论。
- 在负责人签核前发布、招募用户、公开 Beta 或收集用户数据。
- 自动修改 `owner-signoff.md`、`audit-register.md`、`data/review-log.tsv` 或任何评分、状态和日期。
- 本周清理历史 `.scratch/stale-evidence`、重做底图、统一全部场景元数据或处理非核心通路。
- 把历史科学证据欠账直接并入第六周硬验收口径。
