# 负责人逐图签核包

本签核包服务于第六周收口。它只记录项目负责人的人工确认，不替代学习/专家地图内部评分、自动化门禁或科学审校台账。

## 使用顺序

1. 先打开同一通路的学习地图和专家地图，确认两图事实、方向、区室、膜侧和边界一致。
2. 在 390、768、1440 三档视口分别实际操作：进入、查看主图、打开详情、返回和切换相邻出口。
3. 学习图重点看主线、输入、输出、区室、关键步骤和教学顺序；专家图重点看区室、膜侧、转运、反应机制和边界。
4. 没有发现问题时，在 `owner-signoff.md` 将该通路对的两侧状态改为 `通过`，填写确认日期和简短确认说明。
5. 发现问题时保持状态为 `退回`，填写具体问题、视口和证据路径；不要填写 `通过` 或提前增加完成数。
6. 修改只允许覆盖被退回的通路对；修复后重新生成该通路学习/专家两侧的三档 canonical final 证据，运行针对性回归，再等待负责人重新确认。
7. 每次更新后运行 `npm run audit:owner-signoff`，确认报告中的正式完成数、证据数和阻塞项与台账一致。

## 每条通路对的人工检查

对每一行通路依次完成以下项目：

- [ ] 学习图 390：主线和核心标签可读，进入/详情/返回可操作
- [ ] 学习图 768：主图、侧栏和手势不互相遮挡
- [ ] 学习图 1440：信息密度和阅读顺序合理
- [ ] 专家图 390：区室、膜侧、方向、转运和关键标签可读
- [ ] 专家图 768：机制覆盖层、反应列表和导航不重叠
- [ ] 专家图 1440：机制全貌、边界和反应关系可核对
- [ ] 学习图与专家图事实、方向、区室和边界一致
- [ ] 通过审计命令，或记录所有阻塞项

## 状态转换

| 当前状态 | 允许的下一状态 | 必填信息 |
|---|---|---|
| `待确认` | `通过` 或 `退回` | `通过` 要确认日期；`退回` 要问题说明 |
| `退回` | `通过` 或继续 `退回` | 修复证据、针对性回归结果、负责人重新确认日期 |
| `通过` | 仅在负责人明确发现问题时回到 `退回` | 退回原因和对应视口 |

自动化命令只读验证这些约束，不执行状态转换。

## 退回记录格式

在 `owner-signoff.md` 的“备注/退回项”中使用以下信息：

```text
视口：390/768/1440；地图：学习/专家；问题：<可复现描述>；证据：<路径>；范围：仅本通路对
```

退回不得只写“看起来不对”或“需要优化”。应说明具体标签、连线、区室、方向、导航动作或事实边界。
