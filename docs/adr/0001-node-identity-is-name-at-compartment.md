# 节点主键是「名称@区室」

一种物质出现在不同区室里就是不同的节点，所以主键取「名称@区室」的复合值，由程序从
转录的两列拼出来，转录者永远不写 ID。这样同一物质在同一区室里无论参与多少条通路都只有
一个节点（乙酰辅酶 A 出现在 8 条通路里 → 1 个节点被引用 8 次，通路归属挂在反应上），
而同一物质跨两个区室则自然成为两个共享 base 的节点，可以靠 base 自动互链，
PRD §6.2 要求的 PortalLink 因此不需要单独实现。

## 被否决的方案

原先 SVG 层用人工短 ID（`glucose`、`nadh_c`、`atp_m`），49 个节点里已经出现四种互相
矛盾的区室后缀约定：`nadh_c` 给胞质加后缀而基质不加，`malate` 反过来，`atp_m` 又反过来，
`dhap_shuttle` 的后缀根本不表示区室而表示角色。10 组跨区室同物质里有 4 组完全没有连接
反应，即同一物质在两个区室各画一个点却毫无关系——正是缺少 PortalLink 的表现。
继续用短 ID 意味着每加一个节点都要现编一次命名规则。

## 代价

同一物质在同一区室里想出现在两个位置（例如糖酵解和糖异生各画一个葡萄糖以缩短连线）会被
强制合并。导入现有坐标时这真实发生了两次：`磷酸二羟丙酮` 的两个实例相距 341px，
`辅酶 Q` 相距 106px，各保留连接数较多的那个，被舍弃的坐标作为注释留在
`data/layout-overrides.tsv` 里。如果将来确需分开摆放，就要给主键加一个实例列——
这也是当初刻意不留这个口子的原因：先看真实连线效果，再决定值不值得。
