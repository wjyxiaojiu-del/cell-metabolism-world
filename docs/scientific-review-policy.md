# 科学审校与表示类型政策

日期：2026-08-07

## 目的

本政策用于审校 `data/reactions/*.tsv`。它把“证据是否充分”和“地图如何表示”分开，避免用 `已终审-示意边` 之类混合值掩盖科学边界。

## 三个独立维度

### 1. 审校状态

`审校`列只允许以下三个值：

- `待审校`：证据不足、区室/物种未定，或当前表示仍可能误导。
- `已核对`：已与原图、原始资料或人工记录核对，但未完成数据库级复核。
- `已终审`：当前表示的含义、边界和证据均已确认。

表示为示意边、净反应或货物流并不自动等于已终审。只有表示类型明确、备注不冒充精确化学计量、证据可追溯时，才可提升为 `已终审`。

### 2. 表示类型

- `精确反应`：单步或可由数据库反应直接对应的化学反应。
- `净反应`：多个已知步骤合并，反应式表达可核验的净计量。
- `示意边`：表达类别关系或教学概念，不声称精确计量。
- `货物流`：自噬、内吞、囊泡成熟或分泌等细胞过程。
- `转运`：转运方向与载体/机制有可靠依据。
- `机制未明转运`：区室连接有依据，但具体载体或机制未充分确认。

表示类型先记录在 `data/review-log.tsv`。需要驱动页面线型时，再把已批准值加入反应 TSV 的可选 `表示类型` 列；不得从酶名或虚线样式反推科学结论。

### 3. 证据

证据优先级：

1. Rhea：平衡反应、方向、EC 对应。
2. Reactome：人类通路、区室和上下游关系。
3. KEGG：反应、模块和跨物种路径。
4. UniProt：酶功能、EC、亚细胞定位。
5. PubMed：转运机制、细胞事件和近期综述。

引用必须写成可机器识别的形式：`RHEA:30190`、`KEGG:R01513`、`R-HSA-977347`、`PMID:11080587`。示例 ID、搜索摘要和未经打开核对的网页不能作为终审证据。

## 终审门禁

一行提升为 `已终审` 前必须同时满足：

1. 底物、产物、酶、方向和区室与当前物种范围一致。
2. 表示类型明确；非精确反应在备注中直说其抽象边界。
3. 至少一个可靠来源支持核心结论；区室定位优先要求 Reactome/UniProt 或文献支持。
4. 引用已由 `node tools/check-citations.js` 检查格式；可联网时再运行 `--online`。
5. `node tools/validate.js`、`node tools/selftest.js`、`node tools/compile.js --check` 全部通过。

“机制未明”不能仅凭诚实标注就计为精确机制已终审。可以终审的是“当前仅知道存在此区室连接”这一有限结论，并且必须有支持该有限结论的来源。

## 明确否决的做法

- 不使用 `已终审-示意边`、`已终审-货物流` 等非标准审校值。
- 不把附件中的占位 PMID 或未经验证的 Rhea/KEGG ID 写入源数据。
- 不用简单字符串搜索声称完成原子或电荷守恒检查。
- 不把未知转运蛋白替换成“最可能”的蛋白后直接终审。
- 不为了达到 95% 指标而批量提升状态。

## 工作流

```bash
node tools/review-helper.js
node tools/review-helper.js --write
node tools/check-citations.js
node tools/check-citations.js --online
node tools/validate.js
node tools/compile.js
```

`review-helper.js` 默认只读。`--write` 会重建当前待审校清单，同时保留台账中已完成的审计记录，并更新 `REVIEW_PROGRESS.md`；它不会修改反应 TSV。只读外部审核不应使用 `--write`。
